# Marks Entry System — Admin Semester Management

Individual Week 2 module (Group 22) for the SafeX Solutions Marks Entry
System. Lets an admin create and manage **semesters** and, for each
semester, its **enrollment periods**.

Stack: **React (Vite)** frontend, **FastAPI** backend, **PostgreSQL** database.

---

## 2. Prerequisites

- Python 3.10+
- Node.js 18+
- PostgreSQL 14+ running locally (or a connection string to a remote instance)

## 3. Database setup

Create the database (table creation is handled automatically by SQLAlchemy
on first run — you don't need to write CREATE TABLE by hand):

```bash
psql -U postgres -c "CREATE DATABASE marks_entry_db;"
```

## 4. Backend setup

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
```

**Generate your admin login credentials** (do this before starting the server):

```bash
python generate_admin_credentials.py
```

It will ask you to choose a username and password, then print three lines
like this:

```
ADMIN_USERNAME=admin
ADMIN_PASSWORD_HASH=8f2c1a...$9b3e...
JWT_SECRET=6a1f9c...
```

Paste those three lines into your `.env` file (replacing the placeholders),
alongside your `DATABASE_URL`. Your plaintext password is never stored —
only the generated hash goes into `.env`.

Then start the server:

```bash
uvicorn main:app --reload
```

The API is now running at **http://localhost:8000**.
Interactive docs (auto-generated by FastAPI): **http://localhost:8000/docs**

## 5. Frontend setup

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

The app is now running at **http://localhost:5173**.

## 6. What the module does

**Authentication**
- Login screen guards the entire admin panel — nothing is accessible without
  signing in
- Password is never stored in plaintext (PBKDF2-HMAC-SHA256 hash, 200k
  iterations, unique salt per credential)
- Session handled via a signed JWT (2-hour expiry by default), sent as a
  Bearer token on every request
- Every semester and enrollment-period API route requires a valid token;
  an expired or missing token returns 401 and the frontend automatically
  drops back to the login screen

**Semesters**
- Create a semester with a name (e.g. "Fall 2026"), start date, end date,
  and status (`upcoming` / `active` / `completed`)
- List all semesters, edit any semester, delete a semester (also deletes
  its enrollment periods)

**Enrollment Periods** (scoped to a selected semester)
- Add an enrollment window (start/end date, status `open` / `closed`)
  within a semester
- List, edit, and delete enrollment periods for the currently selected
  semester

Validation (both client-side and server-side via Pydantic):
- All fields required
- End date cannot be before start date
- Semester names must be unique

## 7. API reference

| Method | Path | Description |
|---|---|---|
| POST | `/auth/login` | Log in with username + password, returns a JWT |
| GET | `/auth/me` | Returns the logged-in admin's username (for testing a token) |
| GET | `/semesters` | List all semesters |
| POST | `/semesters` | Create a semester |
| GET | `/semesters/{id}` | Get one semester (with its enrollment periods) |
| PUT | `/semesters/{id}` | Update a semester |
| DELETE | `/semesters/{id}` | Delete a semester |
| GET | `/semesters/{id}/enrollment-periods` | List enrollment periods for a semester |
| POST | `/semesters/{id}/enrollment-periods` | Add an enrollment period to a semester |
| PUT | `/enrollment-periods/{id}` | Update an enrollment period |
| DELETE | `/enrollment-periods/{id}` | Delete an enrollment period |

Full interactive schema at `/docs` once the backend is running.
